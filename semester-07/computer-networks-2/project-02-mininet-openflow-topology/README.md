# Mininet and OpenFlow Topology Coursework

Individual **Computer Networks II** coursework completed at Isfahan University of Technology in 2024.

## Overview

This project explores software-defined networking concepts through **Mininet**, **Wireshark**, and a Python-defined network topology.

The assignment combines observation of switch-controller communication with hands-on topology construction. The submitted Python program creates a custom multi-switch topology, connects it to a remote controller, and performs basic connectivity and topology-inspection operations.

## Implemented in the submitted version

The submitted `mini_net.py` defines:

- 8 OpenFlow-capable switches
- 14 hosts
- host-to-switch links
- inter-switch links forming a custom tree-like topology
- a `RemoteController` at `127.0.0.1:6633`
- Mininet startup and shutdown
- `pingAll()` connectivity testing
- topology detail output using `dump()`
- node-list output

## Related analysis

The accompanying report and screenshots cover assignment tasks involving:

- Mininet predefined topologies
- Wireshark capture on the loopback interface
- switch-controller communication
- OpenFlow feature request/reply messages
- Packet-In messages
- ICMP traffic generated by `ping`
- Mininet commands including `dump`, `nodes`, and `pingall`

## Archival validation

During the 2026 archival review, the Python source passed a syntax check with:

```bash
python -m py_compile source/mini_net.py
```

This verifies Python syntax only. The historical topology has not been fully revalidated against current Mininet, Open vSwitch, or controller versions.

## Running the historical topology

A Linux environment with Mininet is required. The submitted script also expects a compatible remote OpenFlow controller listening on:

```text
127.0.0.1:6633
```

A typical invocation is:

```bash
sudo python3 source/mini_net.py
```

Exact behavior can depend on the installed Mininet, Open vSwitch, and controller versions.

## Known limitations

- The controller address and port are hard-coded.
- No controller application is included in the submission.
- The script does not expose command-line configuration for topology parameters.
- The project is educational coursework rather than a reusable SDN framework.
- The original demonstration video is intentionally omitted from the public Git archive because of its size; see `original-submission/README.md`.
